# PowerTimer 0.8.0 RC1 — результаты предварительного аудита

## Выполнено в среде подготовки

- Проанализированы `src-tauri/src/lib.rs`, `native.rs`, настройки Tauri, JavaScript основного окна и трея, политика разрешений, файлы сохранения конфигурации.
- Проверены все четыре действия в списке (`shutdown`, `restart`, `lock`, `logoff`) и условия (`interval`, `clock`, `idle`, `cpu`) по коду.
- Проверены переходы `ready → running → warning → completed`, отмена предупреждения, вызов системных действий через whitelist в Rust, защита тестовым режимом.
- Сохранены обработчики событий трея, отдельный popup и single-instance, отсутствие ручного выполнения shell-команд из интерфейса.
- Выполнены `npm run check` (статические тесты, синтаксис JS); см. результат в сопроводительном ответе.
- Сравнены визуальные исходники `ui/index.html` и `ui/style.css` с базой 0.7.8: без изменений; CSS трея также сохранён. Изменилось лишь отображение версии в меню.

## Исправленные потенциальные регрессии

1. Прямая перезапись `config.ini` могла потерять старые настройки при обрыве записи → запись во временный файл, затем замена.
2. При неоднозначном времени перевод часов мог выбрать завтрашнюю дату вместо второго наступления текущего часа → выбор ближайшего будущего варианта.
3. Неправдоподобное время последнего ввода Windows могло выглядеть как десятки дней бездействия → безопасный сброс такого показания.
4. Расчёт CPU выделен в проверяемую функцию непрерывного пребывания ниже порога.
5. Предупреждение ранее **продлевало** интервал/указанное время → теперь оно предшествует цели, а позднее возобновление требует безопасной паузы.
6. Выход при активном таймере теперь явно записывается в журнал (если включён).
7. Обработчик системного закрытия сначала освобождает блокировку состояния и лишь затем пишет событие в журнал, чтобы не допустить взаимной блокировки при выключенном «Сворачивать в трей».

## Не подтверждено здесь — обязательно на Windows 11

- Сборка Rust и прохождение Rust unit tests (`cargo test`). В среде подготовки нет установленного Rust и Windows SDK.
- Живые тики в фоне, поведение трея и окон, блокировка второго процесса, закрытие и прекращение фоновых потоков.
- Точность показаний системного бездействия и CPU на реальной Windows.
- `npm.cmd run build`, копирование EXE и запуск из отдельной папки.
- Реальные системные действия отключены во всех безопасных тестах; их фактическое выполнение здесь не тестировалось.

## Оставшиеся ограничения по дизайну

- **Активный таймер не переживает полный выход из PowerTimer или перезапуск Windows.** Это сохранённая политика, а не регрессия.
- Точность запуска ограничена частотой опроса 500 мс, планировщиком Windows, паузами сна и загрузкой системы.
- **Предупреждение для CPU/бездействия:** начинается после достижения условия и добавляет время для отмены; фиксированные расписания теперь выполняются в назначенное время.
- Портативному EXE необходим WebView2 Runtime на целевой системе.

**Вывод:** RC1 пригоден для контролируемых Windows-испытаний. Пометка Stable возможна только после результатов из `QA_WINDOWS_RU.md`.
