# PowerTimer 0.8.0 RC3 — аудит под Windows 11

**Статус:** кандидат в стабильный релиз. В среде подготовки выполнены статические проверки JavaScript и структуры проекта. Команды `cargo test`, `npm.cmd run dev` и сборку настоящего EXE нужно выполнить на Windows 11. Наличие этого документа НЕ означает, что эти проверки уже выполнены.

## Безопасность

**Все испытания системных действий проводить только при включённом «Тестовый режим».** Не отключать тестовый режим ради проверки таймера: тест на выключение, перезагрузку и выход из учётной записи может прервать работу Windows и привести к потере несохранённых документов.

## Подготовка

Завершите все экземпляры PowerTimer через трей «Выход», остановите `dev` через `Ctrl+C`. Сохраните рабочую портативную 0.7.8 в отдельной папке; не удаляйте её и не заменяйте готовый EXE до окончания испытаний.

Откройте PowerShell в каталоге проекта и выполните:

```powershell
npm.cmd install
npm.cmd run check
cargo test --manifest-path .\src-tauri\Cargo.toml
npm.cmd run dev
```

Успех: все Node.js- и Rust-тесты завершаются без ошибок; окно PowerTimer открывается, дизайн совпадает с 0.7.8 (1200 × 680, Inter, название по центру).

## Дополнительная проверка прогресса RC2

- Включите тестовый режим, выберите «Интервал»: 00:00:10 и «Предупреждать за»: 5 сек. При появлении модального окна шкала должна быть примерно на **50%**, а не на 100%. Пока предупреждение идёт, шкала должна постепенно расти.
- Для короткого интервала 00:00:04 с предупреждением 2 сек проверьте, что шкала плавно продолжает заполнение; само системное действие в тестовом режиме не запускается.
- В режимах CPU/бездействия с предупреждением выполнение условия должно соответствовать 90% прогресса, а оставшаяся часть шкалы — предупреждению.
- Проверьте отмену во время предупреждения: шкала исчезает и новый таймер начинается с 0%, без унаследованного заполнения.
- Если в Windows включено сокращение анимаций, отсутствие плавного перехода допустимо. Установки Windows не следует менять ради теста.

## Проверки вручную

1. **Интервал:** с тестовым режимом и предупреждением 5 сек задайте 00:00:10. Запустите таймер, проверьте убывание секунд; предупреждение должно начаться примерно на 5-й секунде, а завершение — примерно на 10-й секунде (не на 15-й). Дождитесь окончания: вместо реального выключения должно появиться сообщение о завершённом тесте.
2. **Предупреждение и отмена:** повторите 00:00:10 и нажмите «Отменить» в предупреждении. Системная команда не должна выполняться. Повторите тест: сфокусируйте кнопку «Отменить» и нажмите Enter — должна быть отмена, а не подтверждение.
3. **По времени:** установите локальное время на несколько минут вперёд (не меняйте часы Windows), дождитесь завершения в тестовом режиме. Для уже прошедшего часа цель должна переноситься на следующие сутки. Обработка повторяющегося часа при DST покрыта отдельной проверкой Rust; практическая проверка требует часового пояса с переходами.
4. **Бездействие:** установите одну минуту, начните отсчёт, двигайте мышью — действие не должно срабатывать. Прекратите ввод, подождите минуту и проверьте тестовое завершение. Снятие фокуса с окна допустимо.
5. **Загрузка CPU:** укажите порог, наблюдайте за сбросом прогресса при выходе выше порога. Условие выполняется только если CPU ниже порога заданное непрерывное время. Величины CPU могут колебаться — не требуется добиться срабатывания любой ценой.
6. **Трей:** включите «Сворачивать в трей», скройте окно. Левый клик по значку возвращает **то же окно**, правый открывает тёмное меню с «Отменить таймер» и «Выход». Проверьте отмену при активном таймере.
7. **Журнал:** при включённом журнале проверьте строки запуска, отмены и срабатывания в `Logs\PowerTimerMini.log` рядом с портативным EXE (или в `%APPDATA%\PowerTimerMini\Logs` при отсутствии права записи рядом с EXE). При выходе с активным таймером журнал должен сообщать об остановке.
8. **Настройки:** измените интервал, предупреждение и «Тестовый режим», закройте и запустите снова; значения должны сохраниться в `config.ini`. Проверьте повторное сохранение: `config.ini.tmp` не должен оставаться при успешной записи.
9. **Один экземпляр:** с запущенным PowerTimer попробуйте открыть второй EXE; второе окно не должно создаваться, основное должно появиться.
10. **Выход:** пока работает тестовый таймер, выберите «Выход» в меню трея. Убедитесь, что PowerTimer отсутствует в процессах. Отдельно выключите «Сворачивать в трей», запустите новый тестовый таймер и нажмите крестик окна: программа должна полностью закрыться **без зависания**. Сохранённый таймер после следующего запуска **не должен самовосстанавливаться** (это текущее поведение приложения).

## Release и независимый EXE

Остановите dev через `Ctrl+C`, затем:

```powershell
npm.cmd run build
$exe = Resolve-Path '.\src-tauri\target\release\powertimer.exe'
$folder = 'T:\Downloads\PowerTimer_0.8.0_RC2_Portable'
New-Item -ItemType Directory -Path $folder -Force | Out-Null
Copy-Item $exe "$folder\PowerTimer.exe" -Force
& "$folder\PowerTimer.exe"
```

Проверьте запуск независимо от каталога исходников. Для Windows 11 требуется WebView2 Runtime. Программа не требует Node.js/Rust на компьютере, где запускается готовый EXE.

**Проверка отсутствия фонового процесса после выбора «Выход»:**

```powershell
Get-Process -Name 'PowerTimer','powertimer' -ErrorAction SilentlyContinue |
  Select-Object ProcessName, Id, Path
```

Пустой вывод означает, что процессы с этими именами не обнаружены. При работе через `npm.cmd run dev` может оставаться только терминальный процесс разработки, пока его не остановили.
