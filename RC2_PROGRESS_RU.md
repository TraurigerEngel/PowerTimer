# PowerTimer 0.8.0 RC2 — изменения прогресса

## Выявленная причина

При каждом обновлении ядра в состоянии `warning` ранее выполнялось безусловное `core.progress=100.0`. Поэтому за несколько секунд до действия шкала внезапно заполнялась до конца.

## Новая модель

- `fixed_deadline_progress`: относительный прогресс до исходного дедлайна; предупреждение внутри общего времени и не меняет график.
- `condition_running_progress`: при ненулевом предупреждении резервирует последние 10% для этапа подтверждения.
- `warning_progress`: для CPU/бездействия вычисляет продолжение 90→100; для интервала/времени использует тот же исходный дедлайн.
- CSS использует переход `width 650ms linear`, плавно перекрывающий полусекундные обновления Rust. При снижении анимации переход отключается.

## Проверки

- `npm run check`: **30/30 PASS** (структурные тесты и JavaScript syntax).
- Chromium (локальная имитация снимков состояния): ширина шкалы росла между срезами; предупреждение при 61% не переводило шкалу на 100%; ошибок страницы не было.
- Добавлены **3 Rust unit tests** для предупреждения по фиксированному времени, CPU/бездействия и граничных чисел. Их выполнение требуется подтвердить на Windows через `cargo test`.
- Rust/WIndows Release-сборка в среде подготовки **не выполнялась**. Статус RC2, не Stable.

Примечание: падение напряжения или сон компьютера могут приводить к законному скачку времени вперёд, если установленный срок уже прошёл; безопасность 5-секундного предупреждения сохраняется.
